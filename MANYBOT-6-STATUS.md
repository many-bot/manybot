**08/20 continuation 14 — Phase 1 closed: `import:` mechanism.** `commandsConfig.ts`: new root-level `import:` key (string or list of paths, resolved relative to `PATHS.HOME`); `resolveImports()` reads each referenced YAML file and folds its top-level keys into the main root object before `defaults`/`menu`/`categories`/`manuals`/`specs` are extracted — so an imported file can contribute a `menu:` block, `manuals:`, `categories:`, or full command entries exactly as if they were written inline in `commands.yaml`. Ownership is first-wins, no deep merge: a key already present (from the main file or an earlier import) that reappears in a later import is logged as an error and skipped, keeping the earlier definition; a nested `import:` inside an imported file is ignored with a warning (not recursive — out of scope); a missing/unreadable/malformed import file logs an error and is skipped without failing the rest of the load. Added `import` to `RESERVED_KEYS` so it's never mistaken for a command id. 5 new locale keys (`commandsConfigImport{ReadFailed,ParseFailed,InvalidRoot,Nested,KeyConflict}`) added to `en`/`pt`/`es`. 4 new tests in `commandsConfig.test.ts` (merge from multiple imports, single-path-not-list form, key-conflict-keeps-first, missing/malformed import doesn't fail the load) — **pending local validation** (dev sandbox has no `node_modules`/network); expect 218/218 if these pass as written.
